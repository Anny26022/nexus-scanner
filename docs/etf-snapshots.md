# ETF snapshots

The daily refresh calls TradingView's India scanner once for NSE funds with subtype `etf`. `etf_fields.json` is the shared, versioned registry used by ingestion, the filter dialog and the table. It includes all 2,893 discovered fields; the request also includes listing identity and quote time. Enum display labels were captured from TradingView's `/enum` endpoint on 23 October 2026. These are observed website interfaces, not a guaranteed public API.

The publisher writes a separate packed `etfs.json.gz`, advertised through the optional `etfDatasetUrl` release field. The raw staging file is ignored by Git; only the packed publication is committed. Stocks never include ETF rows or download the ETF snapshot. Both snapshots share the release revision; the worker caches by URL, revision and session. ETF screening is latest-only: no dated R2 archive or historical backend input is created. Once a new release succeeds, older `revisions/*/etfs.json.gz` files are removed from the deployed tree. Stock snapshots and archives are unchanged. Git still retains previously committed ETF versions in commit history; this policy does not rewrite history.

ETF source failures are recorded by the existing pipeline diagnostics. Quotes must match the stock session for at least 90% of listings before an ETF snapshot is advertised. Unavailable/stale ETF input does not stop stock publication and is never carried forward as current ETF data. Fund analytics retain their provider cadence; a current quote does not establish a current NAV or holdings report. Capture time and each listing's quote date are retained.

Select **ETFs** in the existing universe selector. ETFs always use the latest release; the historical session picker and backtest controls are shown only for stocks. The snapshot worker, filter controls, AND/OR groups, table, column picker, pagination, saved screens and CSV export are reused. Only fields populated in the selected session appear as new filter choices. Missing values stay unavailable, including under negation. ETF criteria are isolated from stock presets and stock query/AI parsing. ETF charts require a separate candle-history source and are not enabled by this snapshot feed.

The registry exposes scalar field variants through the existing comparison and multi-select controls. The two derived new-high/new-low controls are omitted because their exact upstream predicate semantics were not validated. The modern display-only rating/pattern maps are retained in ingestion but are not exposed as usable filters; the populated numeric `Recommend.*` scores and `Candle.*` flags are used instead. Six column-only upstream families are also available through the generic controls where populated. No new filter rendering framework or dependency is introduced.
